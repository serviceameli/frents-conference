# Frents — конференционный лендинг

Лендинг для декораторов, студий аренды и команд событий. Четыре воронки, демонстрационные интерфейсы, отдельный блок мобильного приложения и сбор сегментированных заявок.

## Запуск

Node.js ≥22.13.0.

```sh
npm ci
npm run dev
```

Локальный сайт: http://localhost:5173. Сборка: `npm run build`.

## Что реализовано

- Одна страница с четырьмя карточками-вкладками и подробностями под ними.
- Прокат; проекты и личный склад; барахолка с намерением продать/купить; специалисты с намерением найти команду/предложить услуги.
- 4 основных макета, последовательности демонстрационных экранов, 2 макета мобильного приложения.
- Настоящие ссылки на Frents в App Store и Google Play.
- Одна форма с несколькими интересами, именем, контактом и отдельным согласием.
- Серверная валидация, защита от повторной отправки, honeypot, ограничение повторов одного контакта и обработка недоступности хранилища.
- Заявки сохраняются в D1. Контакты не остаются в браузерном хранилище. Публичного API чтения заявок нет.
- После успешной отправки доступны 4 готовых материала, которые можно распечатать или сохранить в PDF.
- UTM и `source` сохраняются в заявке. Параметр `service` открывает нужное направление.
- Поддержка клавиатуры, reduced motion, мобильного меню и закреплённого мобильного CTA.

## Контент и дизайн

- `lib/services.ts` — тексты, преимущества, офферы и CTA четырёх сервисов.
- `app/page.tsx` — структура страницы и лид-форма.
- `components/app-showcase.tsx` — мобильные макеты и дополнительные экраны.
- `app/globals.css` — визуальная система и адаптивность.
- `public/assets` — оригинальный логотип и шрифты Frents, предметные изображения и сгенерированная фотография.
- `public/bonuses` — материалы конференции.
- `docs/funnels.md` — портреты аудитории и логика четырёх воронок.
- `docs/content-status.md` — подтверждённые факты и то, что нужно заменить/утвердить.

## Заявки

`POST /api/leads` записывает имя, контакт, направления, намерения, источник, UTM, версию согласия и время. Адрес посетителя хранится только как хеш для ограничения частоты. У каждого запроса UUID: повтор с тем же UUID и контактом не создаёт дубликат.

Таблица: `leads`, схема: `db/schema.ts`. Доступ владельца к данным — через инструменты базы Sites. Для продакшена также можно подключить существующий backend Frents вместо D1, сохранив контракт формы. CRM и рассылки не подключены.

Локальная база использует `.wrangler/state` (игнорируется Git). После первой сборки применить миграцию:

```sh
node --import ./scripts/sites-env.mjs ./node_modules/wrangler/bin/wrangler.js d1 execute DB --local --config dist/server/wrangler.json --persist-to .wrangler/state --file drizzle/0000_polite_joystick.sql
```

Не применять один и тот же файл повторно к уже инициализированной базе. Миграции публикации управляются Sites.

## Ссылки для QR

После выбора публичного домена:

- `/?source=conference&utm_source=flyer&utm_medium=qr&utm_campaign=decorators-2026`
- `/?service=rental&source=conference` — студии аренды.
- `/?service=projects&source=conference` — декораторы.
- `/?service=market&source=conference` — барахолка.
- `/?service=specialists&source=conference` — специалисты.

Репозиторий GitHub приватный. Текущая публикация Sites — приватный предпросмотр для владельца. Для реального QR нужен публичный адрес и согласованные офферы.
